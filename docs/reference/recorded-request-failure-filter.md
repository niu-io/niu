# Filter recorded request failures

## List, summary and export contract

Use `status=recorded_failure` on the workspace request list and CSV export:

- `GET /admin/v1/organizations/{organization}/projects/{project}/requests?status=recorded_failure`
- `GET /admin/v1/organizations/{organization}/projects/{project}/requests/export?status=recorded_failure`

The legacy path parameter `project` identifies a workspace. This additive filter
selects attempts with a persisted `request_failures` observation. It can find an
SSE failure after HTTP 200 headers, an upstream HTTP refusal, or a recorded
cancellation observation. It does not infer failure from unresolved execution,
missing usage or missing diagnostic writes. Failure classification is separate
from Provider execution, customer charging and the observed delivery HTTP status.

Existing `status=delivery_failed` retains its documented HTTP 400–599 semantics.
Combine `recorded_failure` with `http_status`, key/model/time filters and list
pagination. One response's list and full-range summary share the same snapshot;
CSV uses the same filtering predicate across the complete selected range.
Cross-page reads remain a live view. Unknown status values return 400.
Workspace read permission, no-store responses and customer/procurement boundaries
remain in force. Missing observations are not known success or zero usage.

The JavaScript administration client supports the filter in its query type and
runtime validation:

```ts
const failures = await client.listGatewayActivity(scope, {
  status: 'recorded_failure', httpStatus: 200,
});
const csv = await client.exportGatewayActivity(scope, {
  status: 'recorded_failure',
});
```

Handler annotations, generated OpenAPI/operation references and the root CSV
contract declare this value. See the [request contract](../../contracts/request-observability.openapi.yaml).

## Limits

These runs qualify the stated mixed-success/SSE-error and persisted/unrecorded
HTTP-refusal histories, the SDK integration and scoped report consistency.
They do not qualify every failure type, concurrent diagnostic arrival during
pagination, arbitrary report scale, sustained throughput or browser presentation.
Personal upstream access and approved internal credit are separate from commercial
supply and received cash. Fixture outcomes supply no evidence. Static clippy,
SDK type/build and annotation checks completed separately. The native upgrade
followed a fresh backup restore/comparison and preserved configuration, encrypted
identity and durable business counts.
