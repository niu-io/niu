## Payload protocol coverage review

The current RequestContent/request-content implementation reconstructs JSON Chat Completions choices, JSON Responses output, and streamed Chat Completions indexed choices/tool fragments. It does not reconstruct streamed Responses events: the SSE parser only processes events with a choices array and requires [DONE]. Consequently a retained Responses stream can show no readable response and a partial warning despite containing valid completed events. Raw data remains available. Supporting Responses output-text, output-item/tool events and completed/failed/incomplete terminal events is a required follow-up; it must preserve indexed ordering and avoid duplicating terminal snapshots. The current UI tests qualify existing protocols, not this missing protocol. UUID masking is applied to both displayed and copied content, but that client behavior alone does not establish all backend commercial-data serialization boundaries.

The next parser change adds Responses output-text delta/done reconstruction with output/content index ordering and terminal completed/failed/incomplete handling. A terminal output snapshot takes precedence over text deltas, avoiding duplicate text and restoring completed function-call output. Four payload tests and type checking pass. The live retained Chat Completions detail was inspected after the change; this does not qualify a live Responses request. Partial streamed tool-argument reconstruction and non-text Responses output remain open.

Partial Responses function calls now retain output-item names and accumulated argument deltas by output index; finalized argument/item events replace the assembled snapshot rather than append it. Interrupted streams remain marked partial, and text/tool output follows output-index order. The event contract was checked against https://developers.openai.com/api/docs/guides/function-calling and https://developers.openai.com/api/reference/resources/responses/streaming-events. Five payload tests and type checking pass. Live streamed Responses/tool qualification, refusal and non-text event support remain open; this change does not execute tools.

A temporary, explicitly labeled synthetic Responses stream was rendered with the real RequestContent component and product CSS. Desktop and a 390px embedded viewport verified text ordering, the partial-state notice, expanded function arguments, and desktop switching to Raw data. No saved request or inference was created; the temporary entry and viewport fixture were removed after review. This qualifies renderer interaction/layout for the synthetic partial stream, not live gateway Responses retention.
