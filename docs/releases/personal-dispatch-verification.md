# Personal credential dispatch

Personal upstream usage is paid by the credential owner. It must not create a Niu customer charge, receive Supplier commercial attribution, or bypass workspace authorization.

The storage implementation records an immutable account owner and pins credential and model revisions before dispatch. Shared model discovery excludes personal credentials. The dispatch boundary rechecks owner, enabled states, revisions, workspace key scope, expiry, revocation, model grant, Provider identity and inspection binding. Existing guardrail triggers and workspace budget admission still apply. Commercial requests retain the funded prepaid reservation requirement.

Personal bindings exclude customer tariffs, Supplier offers and customer balance bindings in both insertion orders. Accounting guards lock the attempt to serialize competing assignments. This does not grant funds or activate a commercial offer.

Focused PostgreSQL tests exercise ownership persistence and competition, cross-account route denial, disabled routes, immutable binding, revision changes, commercial accounting rejection, missing inspection evidence and a model disabled after binding. A current personal binding can dispatch from a zero-balance prepaid account without a customer reservation or balance entry. Test credentials are synthetic storage fixtures; these checks send no upstream requests.

The fresh storage regression passes all 97 tests through these migrations. All four focused tests pass after the additional dispatch checks, and storage Clippy passes with warnings denied.
