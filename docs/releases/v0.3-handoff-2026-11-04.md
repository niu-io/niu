## Implemented and recently verified slices

**Task-scoped interface authority.** Approval stores an explicit paid-invocation switch, fixed model names and a fixed interface list (`chat`, `responses`, `messages`, `content`, `decisions`, `embeddings`, `video`). The browser shows only the frequent decisions by default: discovery versus paid invocation, model scope, one-hour duration and the spending boundary. Task context, interface narrowing, management-capability detail, spending basis and expansion policy live behind Advanced options. The task string is self-reported review context, never an authorization input. Exchange copies the switch and interface list atomically; rotation copies both; legacy credentials default to every interface and retain their previous meaning. Each inference route checks its own interface and returns a dedicated actionable 403. No separate trial budget is claimed; the UI states that existing workspace and key spending limits are the enforcement and that owner-funded upstream expense has no cap here.

**Independent invocation authority.** Approval and issued credentials persist `invocation_allowed`; legacy grants retain their original meaning. Exchange copies authority atomically, rotation preserves it, and dispatch/admission enforce it. Management-only credentials receive actionable invocation refusal across Chat, Responses, Messages, GenerateContent, structured decisions, embeddings and video submission. Introspection and integration guidance expose the distinction. Funding, model scope, interface scope and management grants remain additional independent checks.

**Fixed named-model browser approval.** Model calls start off. When enabled, the person selects concrete names from the reviewed workspace's catalog. Selecting all means only the currently listed names. Scope/model changes invalidate consent. Failed, empty or malformed catalogs block invocation approval while permitting an intentional return to management-only access. Organization identity is visible. Existing wildcard API clients retain compatibility.

Eleven focused approval UI tests passed, including the Advanced disclosure, task context, interface narrowing and consent reset. A disposable-PostgreSQL approval/exchange regression adds a configured model after authorization, proves an owner can discover it, then verifies the earlier named key cannot list or invoke it. Browser inspection covered open menus, filter/no matches, individual/all-current choice, Escape, direction-key entry from the filter, Enter selection and desktop/narrow layouts; a later source-built browser run approved a management-only connection, read back the actual interface scope and revoked the credential. Long names, large catalogs and paid-path localized expanded states still need their own acceptance evidence.

**Funding-independent management.** Explicit credential inspection, discovery and routing/evaluation/event management remain available before funding, with handler authorization retained. The frontend gate now agrees with these exceptions. Organization workspace-directory GETs and their supported alias also remain available for member-role interpretation. The previous organization-member directory payment error was reproduced and removed in the local runtime.
