## Scope and decision

The previous recorder covered managed requests with a specifically recognized Qiniu restriction or qualified OpenRouter authentication refusal. It did not represent generic repeated upstream failures, personal routes, or affected workspace members. An empty incident list was never proof of healthy supply. Platform incident details were restricted to platform administrators; the in-app notice appeared while using Admin.

This increment records three distinct managed-route 5xx, connection or timeout failures within five minutes for the same current connection and model-mapping revisions. A single failure remains request evidence. Replayed observations do not add counts. Signals are durably indexed and the incident update is serialized per connection/model. Configuration changes do not resolve an incident: recovery requires a later complete, confirmed successful request under the currently enabled connection and mapping. This evidence is model-scoped and time-specific. It does not certify continuous health, authorize a retry, establish nonexecution, change route selection, or release a billing reservation.

A platform operator sees the existing Admin notice, affected model, condition, recovery guidance and connection link. An authenticated workspace member sees only models for active incidents with a recorded failed attempt in that exact workspace, with a link to their own Logs and guidance to contact the platform operator. No Provider identity, upstream URL, secret, procurement amount, other workspace or request content is returned by that projection. Neither notice is an external message or durable notification-delivery mechanism. Both label an unavailable read as unknown rather than healthy. A verification request can incur charges, and earlier uncertain requests should be inspected first.
