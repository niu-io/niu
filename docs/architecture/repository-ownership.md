# Repository ownership

Niu owns model API access, Provider integration, request accounting and consumption observability. External orchestration products own tasks, agents, scheduling and acceptance, and integrate through public interfaces. Optional correlation metadata does not make task execution a Niu responsibility. See [product focus](../product/product-focus.md). Private product implementation and research remain outside this public tree.

Repository boundaries and URL boundaries are independent. The hosted product uses one domain, `niu.io`, with no separate application subdomain.

## Source and distribution repositories

The codebase separates **source repositories** (where platform, website, and private plugin code are developed) from **distribution repositories** (which contain no business source code and assemble pinned commits into deployable images):

| Layer | Repository | Owns | Public paths |
| --- | --- | --- | --- |
| Source (Public) | `niu-io/niu` | Open-source Gateway, dashboard, model catalog, developer docs, API contracts, SDKs, `plugin-api`, `plugin-sdk`, built-in open-source plugins (`niu/plugins/*`), community image, and shared brand assets/theme tokens | `/models/`, `/docs/`, `/help/`, `/login`, `/installation`, `/generations`, `/chat`, `/activity/…`, `/settings/…`, `/admin/…`, `/providers/…`, `/suppliers/…`, `/workspaces/{workspace}/…`, `/v1/`, `/admin/v1/`, `/catalog/v1/`, `/api/plugins/v1/{plugin_id}/…` |
| Source (Private/Independent) | `niu-io/website` | Marketing homepage, blog, public product comparisons, copy, illustrations, and marketing build | `/`, `/blog/…`, `/compare/…`, `/site-assets/`, `/_astro/`, favicon, robots and sitemap |
| Source (Private) | `niu-io/plugins` | Closed-source commercial and enterprise Plugins (`commercial`, `supply-intelligence`, `sso-scim`, `governance`, `compliance`, `proprietary-providers`, `license`) built against Niu's public `plugin-sdk` | None directly; mounted into `cloud` and `enterprise` distributions via `/api/plugins/v1/{plugin_id}/…` (transitional `/enterprise/api/v1/{module_id}/…`) and build-time UI slots |
| Distribution (Private) | `niu-io/cloud` | Official `niu.io` SaaS release composition (`release-pins.json` pinning `niu` + `website` + `plugins`, Cloud plugin manifest, and production SaaS deployment configuration) | Composes the full `niu.io` origin (`/` marketing + Niu core + open-source & SaaS/enterprise plugins) |
| Distribution (Private) | `niu-io/enterprise` | Self-hosted Enterprise customer release composition (`release-pins.json` pinning `niu` + `plugins` without `website`, on-prem Enterprise plugin manifest, and customer delivery templates) | Customer-hosted origin (`/` redirects to default workspace; Niu core + open-source & self-hosted enterprise plugins) |

The public product builds from this checkout without website or private plugin source. Its image serves the catalog, docs, dashboard, APIs, and any enabled built-in open-source plugins from one listener, with PostgreSQL as an external service. When `NIU_SITE_DIR` is unset (community builds and self-hosted `niu-io/enterprise` deployments), `GET /` redirects to `/workspaces/default/` (entering `/login` when unauthenticated or `/installation` before first-time setup) rather than rendering a marketing landing page; `/login` provides direct links to the public model catalog (`/models/`) and documentation (`/docs/`) so unauthenticated visitors can still browse available models and integration guides. Builds use checked-in brand assets and theme tokens under `branding/`.

The `niu-io/cloud` distribution pins immutable `niu`, `website`, and `plugins` commits and installs the separately built static artifacts into distinct directories. Set `NIU_SITE_DIR` to the website output and `NIU_CATALOG_DIR` to the product catalog output. The Gateway serves both on its existing public listener. Website assets never overwrite catalog, dashboard, or docs assets; website content is not a fallback for unknown APIs or workspace routes. Marketing changes require rebuilding and deploying the composed artifact; this is not runtime remote code loading.

The `niu-io/enterprise` distribution pins immutable `niu` and `plugins` commits for customer-managed self-hosted deployments. It omits `NIU_SITE_DIR` and physically excludes `niu.io`-internal SaaS operations plugins (such as domestic tax invoicing, Provider revenue-sharing settlement, and proprietary supply-margin probing) from the built customer image, while bundling self-hosted enterprise plugins (`license`, `sso-scim`, `governance`, `compliance`, and approved `proprietary-providers`).

Keep cross-product navigation relative to the origin: `/models/`, `/docs/`, and `/workspaces/default/`. Production canonical URLs use `https://niu.io`. Website brand snapshots retain attribution and record the Niu revision from which they were copied; the Niu `branding/` directory remains the shared theme source.

Public header geometry and navigation are owned by `branding/public-header.css` and `branding/public-navigation.json`. Docs and catalog import them directly; the independent website snapshots these contracts and the Niu-specific public header composition, recording the public revision, working-tree state and exact file hashes. Its synchronization command takes an explicit public source checkout; regular website builds verify the snapshot without needing that checkout. All public sections use one-row headers and collapse navigation into a floating menu below the shared narrow-width breakpoint.

Both `niu-io/cloud` and `niu-io/enterprise` compose independently versioned private plugins from `niu-io/plugins` alongside the public core and its built-in open-source plugins. The plugin boundary, capability facets, `plugin-sdk`, manifest registration, health checks and tenant context are specified in [Enterprise and Cloud plugin composition](enterprise-composition.md). Community operation requires no private plugin or license service.

`/docs/` serves standalone public documentation. `/help/` is a dashboard route inside the shared application layout. It embeds the standalone documentation artifact; article navigation updates the dashboard router while retaining its rail and account controls. Dashboard Help links use `/help/`, while public links and canonical URLs use `/docs/`. Neither documentation route requires authentication.

Hosted product comparisons at `/compare/` belong to the independently built website artifact. Community installations without `NIU_SITE_DIR` redirect those entries to the bundled technical documentation comparisons under `/docs/compare/`; they require no website source.
