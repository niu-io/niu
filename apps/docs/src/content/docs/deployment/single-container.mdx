---
title: Single-container deployment
description: Niu's target deployment shape and current packaging status.
---

Niu serves its product homepage, documentation, public model catalog, workspace console, inference API and management API under `niu.io`. One Rust gateway owns the HTTP listener and serves the built static sites; PostgreSQL stores tenants, scoped API keys, operations and attempt evidence. The application image exposes one public port. Compose starts it with PostgreSQL as the only supporting service.

The Dockerfile builds the Rust gateway, TypeScript console and Astro documentation, and packages the static homepage and model catalog into one image. The product URLs are `/`, `/docs/`, `/models/`, `/workspaces/default/`, `/v1/…` and `/admin/v1/…`.

:::caution[Current status]
The current image is an evaluation build. Initial persistence and migrations are implemented. Budget reservations, financial settlement, operator roles, streaming evidence and recovery workers remain in progress. Container qualification is not complete. Do not use this image for production workloads.
:::

## Run the evaluation image

Create a local environment file and replace every placeholder with a unique secret. Generate the Niu tokens with a cryptographically secure generator; keep the admin token separate from client API keys.

```sh
cp .env.example .env
docker compose up --build
```

The product is available on port `2555`. Open `http://localhost:2555/` for the homepage, `/docs/` for documentation, `/models/` for the public catalog, and `/workspaces/default/` for the console. The example route requires an OpenAI API key. Change `config/niu.example.toml` to add or edit model routes before starting the container. Only routes with `public_catalog = true` appear in the public catalog.

## Release requirements

- One Niu image serves inference, management, health, and console assets on one listener.
- PostgreSQL is the only required external service for durable state.
- Provider credentials and bootstrap secrets are injected at runtime and never baked into images.
- Image contents exclude private enterprise code, internal research, and development material.
- Install, upgrade, rollback, backup, migration, and restart behavior are tested as a complete product.

## One-domain routing

All product pages and APIs use the same origin. The workspace name in `/workspaces/:workspace/…` selects a UI route; it does not grant access. Each management and inference request still requires server-validated credentials. Current community setup uses an installation administrator token for management and scoped API keys for inference. Operator sessions and per-workspace roles are a separate release requirement.

The gateway serves HTTP. Terminate HTTPS at the hosting platform's TLS edge and forward requests to the single application port. A unified hostname does not provide TLS by itself. Keep browser API requests same-origin so credentials and logout stay on `niu.io`.

When migrating existing hosts, configure permanent redirects at the TLS edge: `docs.niu.io/<path>` should map to `niu.io/docs/<path>`. Redirect the old console root to `/workspaces/default/` and map prior console sections such as `/keys` and `/usage` to `/workspaces/default/keys` and `/workspaces/default/usage`. In the unified product, `/models/` is the public catalog; the workspace route editor belongs under `/workspaces/default/models`.

The static documentation tree is mounted separately from the console. Missing documentation paths return 404, and unknown `/v1/`, `/catalog/v1/` and `/admin/v1/` endpoints return JSON API errors. Nested workspace links can be opened or refreshed directly. Static routes do not buffer inference responses; streaming remains on the gateway's inference handler.

## Bootstrap an organization and client key

`NIU_ADMIN_TOKENS` grants installation-wide administration. `NIU_DATABASE_URL` is mandatory for native startup; Compose supplies the internal database URL. Client keys are created through the management API, not supplied through `NIU_API_KEYS`.

With the gateway running, use your admin bearer token to:

1. `POST /admin/v1/organizations` with `{"name":"My organization"}`.
2. `POST /admin/v1/organizations/{organization_id}/projects` with `{"name":"My project"}`.
3. `POST /admin/v1/organizations/{organization_id}/projects/{project_id}/keys` with `{"name":"Application","allowed_models":["fast"],"ttl_seconds":86400}`.

Each POST returns `201`. Use the returned IDs in the next path. The key response returns its `token` once; store it securely and use it as the bearer token for `/v1/models` and `/v1/chat/completions`. Every request requires `Content-Type: application/json` when sending a JSON body. Delete the key at the same keys path with `/{key_id}` appended to revoke it (`204`).

Model listings are filtered by the key's explicit grants. Revocation and expiry are rechecked at dispatch admission. These bootstrap endpoints require the installation-wide admin token; project-operator sessions and role administration are still pending.

Non-streaming responses include `x-niu-operation-id` and `x-niu-attempt-id` after dispatch, including provider errors. Streaming responses include these IDs on successful establishment. The OpenAI-compatible streaming adapter persists completion and valid usage at the terminal event. Request `stream_options: {"include_usage": true}` when supported by the provider; the JavaScript SDK does this automatically. Missing/conflicting usage stays unknown, and interrupted streams remain uncertain. SSE events larger than 64 KiB are rejected. `/readyz` checks database availability; `/healthz` reports process liveness.


## Manage keys in the console

Connect with the installation administrator token and open **API keys**. Create or select an organization and project, choose explicit model grants and an expiry, then issue a key. The secret appears once in the tab; dismiss it after saving. It is not stored in browser persistence.

Keys can be rotated or revoked from the table. Rotation immediately revokes the old key and preserves its original permissions and absolute expiry. It is atomic: concurrent rotations produce only one replacement. A lost rotation response cannot reveal the replacement secret again; an administrator must revoke the inaccessible key and issue a new one. Key issuance, rotation and revocation append immutable audit events identifying the bootstrap-administrator actor class. Individual operator attribution still requires operator sessions.

The equivalent APIs add `GET` to the organization, project and key collection paths, and `POST .../keys/{key_id}/rotate`. List responses exclude secrets and hashes and currently return at most 1,000 records; pagination remains pending.
