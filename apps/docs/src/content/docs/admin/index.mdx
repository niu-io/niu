Administration manages the installation-wide settings behind your Niu gateway. It is separate from a customer's workspace and from a Provider's own business portal.

## Open Admin

Sign in with an authorized platform administrator account and open **Admin** in the product rail. For initial installation setup, use the administrator credential at `/installation`; ordinary member sign-in remains at `/login`. A workspace owner does not automatically have platform administration access.

The current dashboard requires installation or platform administrator authority and permission to manage operators. Backend endpoints enforce their own authorization on every request. Read [administrator access](/docs/admin/access/) before provisioning accounts.

## Set up your installation

| Task | Guide | Dashboard destination |
| --- | --- | --- |
| Configure platform currency | [Customer setup](/docs/admin/customers/) | Admin → Settings |
| Set up independently funded customers | [Customer setup](/docs/admin/customers/) | Admin → Customers |
| Connect model supply and credentials | [Providers](/docs/admin/suppliers/) | Admin → Providers |
| Configure customer selling prices | [Customer pricing](/docs/admin/pricing/) | Admin → Pricing |
| Configure supported top-up payment methods | [Payments](/docs/admin/payments/) | Admin → Payment gateways |
| Set deployment branding and appearance | [Branding & theme](/docs/admin/branding/) | Admin → Branding |
| Review saved administrative changes | [Audit logs](/docs/reference/platform-audit/) | Admin → Audit logs |

Configure the platform currency and a payment gateway before workspace features become available. Then qualify Provider models and publish customer selling prices before handing off paid access. Create a workspace key with the intended model grants and limits, and use the [API quickstart](/docs/guides/api-quickstart/) to check an application request. Review its customer-facing usage separately from confidential supply information.

## Guides and generated references

These guides explain administrator workflows. Exact parameters, response types and authorization requirements belong to the generated [REST specification](/docs/api/rest/) and [NiuAdminClient](/docs/api/sdk/niuadminclient/). The route names `vendors`, `organizations` and `projects` remain compatibility contracts; product guidance uses Provider, company and workspace.
