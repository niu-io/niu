<div data-lang="en">

A **Provider** supplies model access through an upstream API service. One Provider can have multiple API credentials, each with its own adapter, endpoint, enabled state and model mappings. Its offers, agreed purchase rates and settlements belong to the same Provider. Provider finances and statistics are currently managed only by platform administrators; no Provider login role or portal is available.

## Operating modes: Internal use and Resale

Niu supports two installation operating modes configured via `NIU_OPERATING_MODE`:

- **Internal use (`NIU_OPERATING_MODE=internal`, default)**: Connects shared upstream Providers for your own organization's workspaces. Imported and enabled model routes are immediately available to authorized workspaces without configuring platform currency, payment gateways, customer selling prices, or commercial offer authorizations.
- **Resale (`NIU_OPERATING_MODE=resale`)**: Operates Niu as a commercial multi-customer service. Before a customer workspace can call a shared Provider route, an administrator must publish the agreed Provider purchase rate, explicitly authorize the exact current offer revision for commercial use, and publish a customer selling price in **Admin → Pricing**.

## Before you connect

Set `NIU_VENDOR_ENCRYPTION_KEY` in the deployment secret store before saving credentials. Back it up separately from PostgreSQL. API reads do not return saved secrets; changing the encryption key without re-encrypting existing data makes those credentials unreadable. See [credential protection](/docs/security/overview/).

## Connect model supply

1. Open **Admin → Providers** and click **New Provider**. Choose a prepared preset (**OpenRouter**, **FastRouter**, **BabelArk**, **Qiniu**, **DeepSeek**) or **Custom** for any OpenAI-compatible, Anthropic Messages, New API, or LiteLLM endpoint.
2. For a prepared preset, enter your upstream API key and click **Connect and import models** to create the Provider, save the encrypted credential, verify the upstream catalog, and import discovered model routes in one step. Or open an existing Provider's **API keys** section to add a credential manually.
3. Configure or review the upstream models exposed by that credential and the public model aliases you intend to offer. Select only capabilities supported by the actual model and adapter.
4. Check the connection and inspect its result. Saving a credential or seeing a model in a catalog does not establish successful generation.
5. Enable the intended mappings, grant the model to a workspace key, and make a bounded [test request](/docs/guides/api-quickstart/).

Use the enabled Provider adapters offered by the configuration UI. Do not infer native protocol, video or tool support from a Provider name alone. [Model routes](/docs/configuration/models/) explains aliases, static configuration, managed-route precedence and capability declarations.

## Choose an integration and review discovered models

In **Settings → Default integration**, choose OpenRouter, New API, LiteLLM or Custom. This identifies the upstream service, independently of the inference API format. Each connection can inherit that default or save its own choice under **API keys → Connection integration**. Clearing an override restores inheritance. Integration changes do not overwrite saved endpoints or credentials.

For OpenRouter, the suggested API base is `https://openrouter.ai/api/v1`. New API and LiteLLM use your instance’s API base, usually ending in `/v1`. Enter or edit the URL in the API-key configuration. Custom and unsupported deployments retain manual model configuration.

Open **Model routes → Add model** to read the upstream inventory with the saved credential. OpenRouter first verifies the current key and requests its filtered catalog across all modalities. New API and LiteLLM expose instance-reported inventory. A successful catalog read does not establish management permission, successful inference, commercial authorization or sufficient funds.

Select a model, review its alias and reported metadata, and choose the route settings before saving. Missing metadata remains unknown. Optional inference capabilities are not enabled by discovery. Updating metadata on an existing route preserves its purchase rates; published catalog prices, agreed purchase rates and workspace selling prices remain separate. Publish rate changes through their respective pricing workflows.

If discovery fails, inspect the error, fix the credential or endpoint, and retry. You can also enter an upstream model ID manually. A rejected credential is not silently replaced by public inventory. If another administrator changes the integration while your page is open, reload the saved integration before trying to save again; reloading replaces the unsaved selection.

## Manage the Provider lifecycle

Provider sections include **Overview**, **API keys**, **Models**, **Usage**, **Settlements**, **Members** and **Settings**. Keep credential rotation and enabled-state changes scoped to the selected credential; they must not replace the Provider identity or unrelated model mappings.

Keep customer selling prices separate from Provider offers. Procurement rates, upstream expenses and platform margins belong to authorized platform administration; customer reports expose customer charges only. Provider membership does not enable portal access. Platform administrators manage financial and statistics records and can provide externally reviewed billing exports when needed.

For commercial supply in **Resale** mode, publish the agreed purchase rate, then have an authorized platform administrator explicitly enable the offer for its exact current revision. That action records the commercial authorization and pauses or invalidates it when the rate, route or credential changes. A personal upstream credential used for testing cannot supply a commercial offer. Authorization does not prove live upstream access, and customer selling prices and selling eligibility remain separate workspace decisions.

## Connection incidents

When upstream inference or connection verification encounters authentication failures (`401`), account/permission restrictions (`403`), or repeated upstream credential rejections, Niu records a connection incident visible in **Admin → Incidents** (`/api/v1/incidents`). Inspect the affected Provider, credential and upstream status code, rotate or repair the credential in **Admin → Providers**, and re-verify the connection to resolve the incident.

## Video routes

For a supported video adapter, configure the concrete model and its supported capabilities before exposing it to users. Materials, reference assets and verification are separate scoped workflows; a saved credential does not enable every upstream video operation. Follow the [video guide](/docs/reference/video/) for supported jobs, result handling and current boundaries.

The [REST specification](/docs/api/rest/) and [NiuAdminClient](/docs/api/sdk/niuadminclient/) contain the exact Provider-management interfaces.

<div data-lang="zh" data-title-zh="模型供应商管理">

**模型供应商**（**Provider**）通过上游 API 服务提供模型访问能力。一个模型供应商可以配置多个 API 凭证，每个凭证都可以拥有各自独立的适配器、端点、启用状态和模型映射。其供应报价（offers）、约定采购费率及结算记录均归属于同一个模型供应商。模型供应商的财务与统计记录目前仅由平台管理员统一管理；系统不提供独立的模型供应商登录角色或供应商门户。

## 运行模式：内部使用与商业转售

Niu 支持通过 `NIU_OPERATING_MODE` 配置两种安装实例运行模式：

- **内部使用（`NIU_OPERATING_MODE=internal`，默认）**：为您自身组织的工作空间连接共享上游模型供应商。导入并启用模型路由后，已授权的工作空间即可直接调用，无需配置平台结算币种、支付网关、客户销售价格或商业供应报价授权。
- **商业转售（`NIU_OPERATING_MODE=resale`）**：将 Niu 作为面向多客户的商业化服务运行。在客户工作空间调用共享模型供应商路由之前，平台管理员必须先发布约定采购费率、针对当前确切的报价修订版本显式启用商业供应授权（commercial authorization），并在**管理后台 → 定价配置**（**Admin → Pricing**）中发布客户销售价格。

## 连接前的准备

在保存任何凭证之前，请先在部署环境的机密存储中设置 `NIU_VENDOR_ENCRYPTION_KEY`，并将其与 PostgreSQL 分开备份。API 读取操作绝不会返回已保存的密钥明文；如果在未重新加密现有数据的情况下更改加密密钥，已保存的凭证将无法读取。请参阅[凭证保护](/docs/security/overview/)。

## 连接模型供应

1. 打开**管理后台 → 模型供应商**（**Admin → Providers**）并点击**新建模型供应商**（**New Provider**）。选择预设模板（**OpenRouter**、**FastRouter**、**BabelArk**、**Qiniu**、**DeepSeek**），或选择 **Custom** 配置任意 OpenAI 兼容、Anthropic Messages、New API 或 LiteLLM 端点。
2. 使用预设模板时，输入上游 API 密钥并点击**连接并导入模型**（**Connect and import models**），即可一步完成创建模型供应商、加密保存凭证、校验上游目录并导入所发现的模型路由；您也可以打开现有模型供应商的 **API 密钥**（**API keys**）部分手动添加凭证。
3. 配置或核对该凭证所暴露的上游模型，以及您计划公开提供的模型别名。请仅勾选实际模型和适配器确实支持的能力。
4. 执行连接检查并查看检查结果。保存凭证或在目录中看到某个模型，并不代表模型生成调用一定能够成功。
5. 启用预期的模型映射，将该模型授权给工作空间密钥，并发起一次有界的[测试请求](/docs/guides/api-quickstart/)。

请使用配置界面中提供的已启用模型供应商适配器。切勿仅凭模型供应商名称就推断其支持原生协议、视频生成或工具调用。[模型路由](/docs/configuration/models/)详细说明了模型别名、静态配置、托管路由优先级以及能力声明。

## 选择集成并审阅发现的模型

在**设置 → 默认集成**（**Settings → Default integration**）中选择 OpenRouter、New API、LiteLLM 或 Custom。集成标识上游服务，与推理 API 格式相互独立。每个连接可以沿用该默认值，也可以在 **API 密钥 → 连接集成**（**Connection integration**）中保存自己的选择；清除覆盖值后恢复继承。更改集成不会覆盖已保存的端点或凭据。

OpenRouter 建议使用 `https://openrouter.ai/api/v1`。New API 和 LiteLLM 应使用您自己实例的 API 基础地址，通常以 `/v1` 结尾。在 API 密钥配置中填写或编辑此地址。Custom 及不受支持的部署仍可手动配置模型。

打开**模型路由 → 添加模型**（**Model routes → Add model**），使用已保存的凭据读取上游目录。OpenRouter 会先验证当前密钥，再请求覆盖全部模态的筛选目录；New API 和 LiteLLM 返回实例报告的目录。目录读取成功不代表具备管理权限、推理成功、商业供应资质或充足余额。

选择模型后，先审阅别名、上游报告的元数据和路由设置，再保存。缺失的元数据保持未知；目录发现不会自动开启可选推理能力。更新已有路由的元数据会保留其采购费率；公开目录价格、约定采购费率和工作空间销售价格始终分开。价格变更应通过各自的定价流程发布。

发现失败时，请查看错误，修正凭据或端点后重试，也可以手动输入上游模型 ID。凭据被拒绝时，不会悄悄用公开目录代替。如果其他管理员在您打开页面后修改了集成，请先重新读取已保存的集成再保存；重新读取会替换尚未保存的选择。

## 管理模型供应商生命周期

模型供应商管理页面包含**概览**（**Overview**）、**API 密钥**（**API keys**）、**模型**（**Models**）、**用量**（**Usage**）、**结算**（**Settlements**）、**成员管理**（**Members**）和**设置**（**Settings**）等部分。请将凭证轮换和启用状态变更限制在所选凭证的范围内；这些操作不应替换模型供应商本身的身份或影响无关的模型映射。

请将面向客户的销售价格与模型供应商报价严格分开。采购费率、上游支出和平台利润属于授权平台管理范畴；面向客户的报告仅展示客户费用。模型供应商成员身份不会开启独立的门户访问权限；平台管理员统一管理财务与统计记录，并可在需要时导出经外部核对的账单报表。

在**商业转售**（**Resale**）模式下提供商业化模型供应时，请先发布约定采购费率，然后由经授权的平台管理员针对当前确切的报价修订版本显式启用商业供应授权。该操作会记录商业授权状态，并在费率、路由或凭证发生变更时自动暂停或失效。用于测试的个人上游凭证不能用于商业供应报价。完成商业授权并不证明实时上游访问一定可用，客户销售价格与销售资格仍然是独立的工作空间决策。

## 连接故障事件（Connection incidents）

当上游模型推理或连接检查遇到认证失败（`401`）、账户/权限受限（`403`）或持续的上游凭证拒绝时，Niu 会生成一条连接故障记录，并展示在**管理后台 → 连接故障**（**Admin → Incidents**，对应 `/api/v1/incidents`）中。请检查受影响的模型供应商、凭证与上游状态码，在**管理后台 → 模型供应商**中轮换或修复凭证，并重新验证连接以解除故障状态。

## 视频路由

对于受支持的视频适配器，在向用户开放之前，请先配置具体的模型及其受支持的能力。素材、参考资产与资质验证属于各自独立的作用域工作流；保存一条凭证并不会自动启用上游的所有视频操作。有关受支持的任务类型、结果处理及当前能力边界，请遵循[视频指南](/docs/reference/video/)。

[REST 规范](/docs/api/rest/)与 [NiuAdminClient](/docs/api/sdk/niuadminclient/) 提供了确切的模型供应商管理接口定义。
