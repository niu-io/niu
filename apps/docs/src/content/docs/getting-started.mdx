## Just want to call a model?

You do not need to define tasks, import agent traces, run benchmarks, configure subscriptions or enable pooling.

1. Start the gateway using the [single-container guide](/docs/deployment/single-container/), or the development steps below.
2. Open the console at `http://localhost:2555/workspaces/default/` and use the installation admin session to connect a provider, add its credential, and publish a model alias. For file-managed deployments, configure the same route in `config/niu.example.toml`; the console reports configuration it cannot edit. The example alias is `fast`.
3. Choose **API keys**, select the model alias your app may use, and create a project key. On a new installation, choose **Create workspace and key** to create the default project and a 30-day key shown once. The installation admin credential is for setup; applications use this scoped client key.
4. Point your client to Niu's base URL and make a standard chat request:

```sh
export NIU_API_KEY='your-issued-client-key'
curl http://localhost:2555/v1/chat/completions \
  -H "Authorization: Bearer $NIU_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"fast","messages":[{"role":"user","content":"Hello"}]}'
```

The base URL for compatible clients is `http://localhost:2555/v1`. The gateway
automatically records request metadata, timing and reported usage. Open **Tasks**
in the console to see the request; no run-log export or import is needed. When a
price is configured, the console also shows known cash and API-equivalent cost.
Keep the admin token for administration; applications use scoped client keys.

Pricing schedules and budgets are optional. If you enable a budget, its reservation requirements apply; see [model pricing](/docs/configuration/models/#optional-text-route-pricing). Task grouping and benchmarking are progressive workflows, not prerequisites for inference or automatic request capture. Provider and model routes still use server-side configuration; the first-run console flow handles workspace and client-key setup.

## Requirements

- Rust 1.98.0 for the current selected native runtime modules.
- Node.js 24 or newer and pnpm 11 for the console and documentation workspace.
- PostgreSQL 17 for durable state.
- A configured provider credential for live inference requests.

## Install workspace dependencies

From the repository root, install the JavaScript workspace and build the console and docs:

```sh
pnpm install
pnpm build:console
pnpm build:docs
pnpm build:catalog
```

Check the Rust workspace with:

```sh
cargo check --workspace
```

The gateway expects `NIU_DATABASE_URL`, an admin token, and a model configuration file. Create scoped client keys through the bootstrap administration API. Follow the deployment guide for the configuration format before starting the runtime.
