---
title: Security overview
description: Security boundaries that underpin Niu's performance and cost goals.
---

Security is a product foundation. Performance and cost optimizations must preserve authorization, credential ownership, tenant separation, and any required policy decisions.

## Credential ownership

Provider credentials remain server-side. Public model names resolve through approved routes; requests cannot override provider, credential, or endpoint settings. Logs and browser responses must not contain secrets.

## Authorization

Inference API keys have explicit model grants, project ownership, expiry and revocation. Administration accepts the configured `NIU_ADMIN_TOKENS` bootstrap secret and persistent operator session tokens. Bootstrap tokens have owner authority. Operator roles are installation-wide: `owner` manages operators and can read or write management resources, `admin` can read and write those resources, and `viewer` can read them. A workspace slug in a URL is presentation state and does not scope authority.

Operator session tokens are generated by an owner, returned once with `Cache-Control: no-store`, stored only as SHA-256 hashes and rejected after expiry or revocation. Session lifetimes range from 60 seconds to one year. Revoke an operator to revoke all its sessions, or revoke one session independently. The bearer token is held in console memory and is cleared on disconnect or page reload. These are token-based operator sessions; interactive password, OIDC/SAML, per-workspace role grants and attributable audit actors are not implemented yet.

## Data handling

Every protocol adapter must document what request and response data it transforms, buffers, records, or sends to a provider. Streaming behavior and output inspection need explicit limits and failure semantics.
