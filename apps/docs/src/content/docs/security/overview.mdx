title: Security overview
description: Security boundaries that underpin Niu's performance and cost goals.
---

Security is a product foundation. Performance and cost optimizations must preserve authorization, credential ownership, tenant separation, and any required policy decisions.

## Credential ownership

Provider credentials remain server-side. Managed vendor credentials are encrypted in PostgreSQL with AES-256-GCM using `NIU_VENDOR_ENCRYPTION_KEY`, held separately in the deployment secret store. Only installation administrators can manage these shared connections; organization/project operators cannot. Management APIs never return provider credentials. Back up the encryption secret separately from database backups; automatic master-key rotation is not implemented. Public model names resolve through approved routes; requests cannot override provider, credential, or endpoint settings. Logs and browser responses must not contain secrets.

## Authorization

Inference API keys have explicit model grants, project ownership, expiry and revocation. Administration accepts the configured `NIU_ADMIN_TOKENS` bootstrap secret and persistent operator session tokens. Bootstrap tokens have installation authority. Each operator belongs to one organization and may be limited to one project. Within that scope, `owner` manages operators and can read or write management resources, `admin` can read and write those resources, and `viewer` can read them. A project owner cannot grant organization-wide access or access to another project. A workspace slug in a URL is presentation state; the server enforces the credential's actual scope.

Operator session tokens are generated by an owner, returned once with `Cache-Control: no-store`, stored only as SHA-256 hashes and rejected after expiry or revocation. Session lifetimes range from 60 seconds to one year. Revoke an operator to revoke all its sessions, or revoke one session independently. The bearer token is held in console memory and is cleared on disconnect or page reload. Operator and session lifecycle writes append immutable metadata-only audit events with installation/operator actor attribution. Interactive password login and OIDC/SAML are not implemented yet.

`GET /admin/v1/session` returns the authenticated operator's scope and role permissions, or identifies an installation bootstrap credential. The console uses this response to present available actions. Every API call checks authorization again, so hiding or enabling a control does not grant authority. Private API responses are marked `Cache-Control: no-store`.

Upgrading from unscoped operator credentials revokes those legacy operators and sessions. Use an installation bootstrap credential to create replacement operators with explicit organization/project scope.

## Data handling

Every protocol adapter must document what request and response data it transforms, buffers, records, or sends to a provider. Streaming behavior and output inspection need explicit limits and failure semantics.
