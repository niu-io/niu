## 01 / Where New API is ahead

New API documents a broad selection of upstream integrations and protocol conversions. If a particular service, client, or deployment workflow is essential, start with its documented support and verify it on the version you intend to run. Niu does not claim parity with that integration surface.

## 02 / Where Niu is useful

Niu makes Providers and customer workspaces separate scopes. Its public contracts distinguish customer charges from upstream costs, preserve unknown usage and unsettled charge states, and connect request investigation to saved gateway evidence. Read the supported contracts before relying on a workflow.

See [model configuration](/docs/configuration/models/), [request logs](/docs/concepts/execution-observation/), and the [API contracts](/docs/reference/api/) for supported behavior.

## 03 / Which one to pick

Choose New API when its upstream integrations and instance-management workflows meet your needs. Evaluate Niu when its workspace access, Provider configuration, and request-accounting model fits your application. Both require you to operate storage, configure authorized upstream access, and verify the routes you expose.

Niu’s first feature-complete release has not yet been qualified. Confirm the model, protocol, authorization, and billing behavior required by your workload before choosing a deployment.

## 01 / New API 的领先之处

New API 文档记录了极其丰富的上游集成与协议转换能力。如果某项特定的服务、客户端或部署工作流对您至关重要，请优先参考其文档支持说明，并在您计划运行的具体版本上进行验证。Niu 不宣称在集成广度上与之对等。

## 02 / Niu 的适用场景

Niu 将模型供应商与客户工作空间划分为独立的作用域。其公开契约严格区分客户扣费与上游采购成本，保留未知用量与未结算扣费状态，并将请求排查与已保存的网关证据相关联。在依赖某个工作流之前，请先阅读受支持的契约说明。

有关受支持的行为，请参阅[模型配置](/docs/configuration/models/)、[请求日志](/docs/concepts/execution-observation/)和 [API 契约](/docs/reference/api/)。

## 03 / 如何选择

当 New API 的上游集成和实例管理工作流满足您的需求时，请选择 New API。当 Niu 的工作空间访问控制、模型供应商配置和请求核算模型契合您的应用架构时，请评估 Niu。两者都要求您自行运维存储、配置经过授权的上游访问，并验证对外暴露的路由。

Niu 的首个功能完整版本尚未完成发布验收。在选择部署方案之前，请确认您的工作负载所需的模型、协议、授权和计费行为。
