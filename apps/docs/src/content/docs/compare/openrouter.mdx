## 01 / Where OpenRouter is ahead

OpenRouter gives applications a hosted catalog and documented Provider routing controls without asking you to deploy a gateway or maintain its database. Its API and client SDKs are a direct starting point when you want hosted model access.

## 02 / Where Niu is useful

Niu is useful when you want to operate the gateway and its saved workspace request records, configure your own Providers, and manage application keys through its public interfaces. Hosting Niu does not make an upstream model local or eliminate the upstream service’s data policy.

See [model configuration](/docs/configuration/models/), [request logs](/docs/concepts/execution-observation/), and the [API contracts](/docs/reference/api/) for supported behavior.

## 03 / Which one to pick

Choose OpenRouter for hosted catalog access and Provider routing with less gateway operational work. Evaluate Niu when you need to operate its workspace and Provider workflows. You can configure OpenRouter as an upstream Provider in Niu; the additional gateway still needs deployment, monitoring, and route qualification.

Niu’s first feature-complete release has not yet been qualified. Confirm the model, protocol, authorization, and billing behavior required by your workload before choosing a deployment.

## 01 / OpenRouter 的领先之处

OpenRouter 为应用程序提供了托管模型目录和完善的供应商路由控制，无需您部署网关或维护数据库。当您需要托管模型访问服务时，其 API 和客户端 SDK 是最直接的起点。

## 02 / Niu 的适用场景

当您希望自主运维网关及其保存的工作空间请求记录、配置自己的模型供应商，并通过公开接口管理应用密钥时，Niu 非常适用。但自托管 Niu 并不会将上游模型变成原生本地模型，也不会消除上游服务的数据处理策略。

有关受支持的行为，请参阅[模型配置](/docs/configuration/models/)、[请求日志](/docs/concepts/execution-observation/)和 [API 契约](/docs/reference/api/)。

## 03 / 如何选择

若希望以更少的网关运维工作获得托管目录访问与供应商路由能力，请选择 OpenRouter。若您需要自主运行工作空间与模型供应商管理工作流，请评估 Niu。您也可以在 Niu 中将 OpenRouter 配置为上游模型供应商；但额外部署的网关仍需要您负责部署、监控和路由验收。

Niu 的首个功能完整版本尚未完成发布验收。在选择部署方案之前，请确认您的工作负载所需的模型、协议、授权和计费行为。
