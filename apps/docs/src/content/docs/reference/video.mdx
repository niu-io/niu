<div data-lang="en">

Niu provides implemented video APIs and a typed JavaScript SDK. Start with
`video.generate()`; use Niu model aliases, task references and asset references.
The configured Provider adapter translates them to the upstream service. Clients
do not send Volcengine Actions, upstream asset identifiers or Provider credentials.

## Current availability

| Capability | Implementation and actual verification |
| --- | --- |
| Text-to-video | Implemented. Personal FastRouter Seedance 2.5 creation, task recovery, result retrieval and complete video decoding have actual evidence. |
| Asynchronous tasks | Implemented create/read/list/refresh/wait, persistent state, restart recovery and identical-request replay. Acceptance is not completion. |
| Results | Implemented availability, authorized binary download and result deletion. A successful task can have an expired or deleted result. |
| Provider asset groups and assets | Implemented management and explicit refresh. Actual group creation, video asset creation and Active recovery are verified. |
| Asset-reference generation | Implemented Niu asset-ID resolution and authorization. One actual upstream request returned 403; safe unknown state and no-resend replay are verified. Successful reference output remains unverified. |
| Verification sessions | Implemented creation, metadata, refresh and private H5-link handoff. Actual session creation, encrypted persistence and natural expiry are verified; human completion remains unverified. |
| Usage and billing | Implemented observations, billing and timings. A real result reports 257277 video tokens. Positive customer-priced media settlement remains unverified. |

Available models, inputs and controls depend on the installation's saved
Provider mappings, the selected workspace API key's grants and current policy.
Use model discovery to select an authorized route and inspect its video schema;
do not assume one Seedance version, duration, resolution or fixed preset.
Personal self-funded Provider verification does not establish customer pricing
or commercial supply qualification.

## Generate, wait and download

Use the workspace API key with the selected model grant. The examples import
`@niu-io/sdk`, whose source lives in `sdks/javascript`; build the workspace package
with `pnpm --filter @niu-io/sdk build` before using its compiled entry point.
`NIU_BASE_URL` is the Niu API base ending in `/v1`, not the upstream Provider URL.
Keep the API key in your application's server environment.

```ts
import { NiuClient } from '@niu-io/sdk';

const niu = new NiuClient({
  baseURL: process.env.NIU_BASE_URL,
  apiKey: process.env.NIU_API_KEY!,
});

const models = await niu.video.models.list();
// Check the chosen model's input_types, controls, mode and output first.

// Keep this key with this exact request for uncertain-submission recovery.
const idempotencyKey = crypto.randomUUID();
const job = await niu.video.generate({
  model: 'fastrouter/seedance-2.5',
  prompt: 'A quiet ocean at sunrise, with slow camera movement.',
  durationSeconds: 5,
  resolution: '1080p',
  aspectRatio: '16:9',
  seed: 42,
  watermark: false,
}, { idempotencyKey });

const completed = await niu.video.jobs.wait(job.id, {
  intervalMs: 5_000,
  timeoutMs: 600_000,
});

if (completed.status === 'succeeded') {
  const availability = await niu.video.jobs.results.status(job.id);
  if (availability.video === 'available') {
    const response = await niu.video.jobs.results.retrieve(job.id, 'video');
    const bytes = await response.arrayBuffer();
    // Save bytes in your application's durable storage, or stream the response.
  }
}
```

`video.generate()` maps `durationSeconds` to `duration`, `aspectRatio` to `ratio`,
and the other named fields to the Niu request contract. Extra model-specific
fields use `controls`, for example `omni_reference_task_type` when the model
explicitly declares it. Named fields cannot be overridden through `controls`.
No universal Seedance ranges or prices are assumed. `video.jobs.create()` also
accepts the lower-level Niu `VideoCreateRequest` document.

### Recovery and uncertain state

Niu stores the task, original submission identity and observations in its backend.
Use `jobs.list()` and `jobs.retrieve()` to recover authorized saved tasks after
restart or browser-cache loss. `jobs.refresh()` makes an explicit query for an
already bound upstream task. `jobs.wait()` reads and refreshes saved state; it
never submits another generation.

| Status | Client action |
| --- | --- |
| `queued`, `running` | Continue waiting or retrieve saved state later. |
| `succeeded` | Check result availability before downloading. |
| `failed` | Read observations and timings; do not treat failure as a successful result. |
| `submission_unknown`, `reconciliation_required` | Preserve the original identity and inspect diagnostics; waiting returns this state without an automatic resubmission. |
| `unknown` | The wait helper permits one refresh of the initially unknown saved job, then returns unresolved unknown state. |

Replay the exact creation document with its original idempotency key to recover
the saved attempt. Changed input with that key conflicts. A 202 response does not
prove upstream completion; an uncertain request must not be replaced with a new
key to make it run again. Aborting the wait cancels local waiting and HTTP requests,
not the upstream video task. There is no upstream task-cancellation API here.

## Provider asset management

`niu.media` manages upstream-backed assets through Niu-scoped references. It is
separate from workspace library uploads. The selected model must enable the
supported Provider asset channel, and upstream operation permissions still apply.
Reads and explicit refreshes require the model alias. Mutations support a canonical
UUID idempotency key; updates/deletes may use the current decimal-string revision.

```ts
const model = 'fastrouter/seedance-2.5';
const groups = await niu.media.groups.list({ model, limit: 20 });
const assets = await niu.media.assets.list({ model, limit: 20 });

// Creating a group/asset is a one-shot upstream operation.
const groupOperation = await niu.media.groups.create({
  model, name: 'Reference videos',
}, { idempotencyKey: crypto.randomUUID() });

if (groupOperation.group?.status === 'ready') {
  const assetOperation = await niu.media.assets.create({
    model,
    group_id: groupOperation.group.id,
    kind: 'video',
    name: 'Approved reference clip',
    url: process.env.APPROVED_REFERENCE_VIDEO_URL!,
  }, { idempotencyKey: crypto.randomUUID() });
  if (assetOperation.asset) {
    const saved = await niu.media.assets.refresh(assetOperation.asset.id, model);
    // Wait for actual status "active" before considering it as a reference.
  }
}
```

The source URL must satisfy the channel's accepted HTTPS and media rules and be
fetchable by the upstream service. An authenticated Niu library URL is not
implicitly a public Provider upload URL. A pending/unknown mutation is not an
acknowledgement; recover its saved operation without resending it.

| HTTP endpoint | JavaScript SDK |
| --- | --- |
| `GET`, `POST /v1/media/groups` | `media.groups.list()`, `media.groups.create()` |
| `GET`, `PATCH`, `DELETE /v1/media/groups/{id}` | `media.groups.retrieve()`, `.update()`, `.delete()` |
| `POST /v1/media/groups/{id}/refresh` | `media.groups.refresh()` |
| `GET`, `POST /v1/media/assets` | `media.assets.list()`, `media.assets.create()` |
| `GET`, `PATCH`, `DELETE /v1/media/assets/{id}` | `media.assets.retrieve()`, `.update()`, `.delete()` |
| `POST /v1/media/assets/{id}/refresh` | `media.assets.refresh()` |
| `GET /v1/media/operations` | `media.operations.list()` |
| `GET /v1/media/operations/{id}` | `media.operations.retrieve()` |

### Separate preparation from dispatch

`media.operations.prepare(input, { idempotencyKey })` saves the canonical
operation without sending a Provider request. Retain the exact typed input and
UUID. Dispatch requires a confirmed prepared record, its operation reference,
the same original input and the same idempotency key. Reading a recovered
prepared record never authorizes automatic dispatch. Original material URLs are
not retained in operation history, so an unloaded client cannot invent a resume
payload.

Only an unclaimed preparation can be canceled. Unknown or acknowledged outcomes
remain read-only. `admin.cancelPreparedMediaOperation(scope, operationId, model)`
uses current workspace Write permission and can abandon a saved preparation
after its original inference key expires or is revoked. It does not restore
inference authority or send a Provider request. Current-key cancellation also
remains available through `media.operations.cancel()`.

Read saved operations using `admin.mediaOperationHistory(scope, { keyId, model })`.
The original key may be expired or revoked; current workspace Read permission
governs access. This scope includes all saved accounts for that exact key and
model. Supply `contextGroupId` to pin a saved group's immutable account binding.
Use `list`, `retrieve` or `retrieveByIdempotency` without refreshing Provider state
or restoring execution permission.

Preparation, cancellation and historical reads have current-input API, built SDK
and independent persistence qualification. Dispatch success and response-loss
recovery in the browser require separate qualification.

### Use an asset as a generation reference

```ts
// Only when discovery declares this reference kind, role and control.
const activeAsset = assets.data.find(asset => asset.status === 'active' && asset.kind === 'video');
if (!activeAsset) throw new Error('An authorized active video asset is required');
const referenceJob = await niu.video.generate({
  model,
  prompt: 'Continue the motion in the approved reference clip.',
  references: [{ assetId: activeAsset.id, role: 'reference_video' }],
  controls: { omni_reference_task_type: 'reference' },
}, { idempotencyKey: crypto.randomUUID() });
```

Here `activeAsset` is the returned Niu asset record with status `active`. The
backend checks scope, acknowledgement, parent group, current account/model,
key grants and policy again before dispatch. Do not pass an upstream asset ID
or an `asset://` URI. Ordinary URL references use `{ kind, url, role }`; inline
images, optional inspected/library references and their constraints retain their
separate model/authorization contracts. Asset management availability does not
establish reference-generation support. Inspect the selected model's admitted
reference inputs and controls before submitting a reference request.

The dashboard Materials page restores saved operations under the explicitly selected workspace, API key and model context. **Check saved status** reads the retained operation only; it does not retry a mutation or establish material readiness. Prepared and unknown outcomes remain unconfirmed and block new material/group writes. A failed history read retains existing records with an explicit error. A missing record never proves that the request was not sent; transport uncertainty before a durable record exists cannot currently be recovered after leaving the page.

## Verification-session handoff

This is an upstream human-verification session, not local face recognition.
Ordinary text generation does not require it. Create a session only when your
selected upstream workflow needs it and the caller is authorized.

```ts
const created = await niu.media.verification.create({
  model,
  subjectName: 'Your authorized subject name',
}, { idempotencyKey: crypto.randomUUID() });
const session = created.data;
const handoff = await niu.media.verification.link(session.id, model);
// Present handoff.verification_url only to the authorized user; keep it private.
// After the user finishes, make an explicit observation:
const observed = await niu.media.verification.refresh(session.id, model);
```

Metadata reads omit the private upstream token and link. The link endpoint uses
no-store/no-referrer handling; expired sessions do not regain a valid link after
restart or encryption rotation. This implementation does not assert that the
human flow has been completed or that an account obtained additional entitlement.

| HTTP endpoint | JavaScript SDK |
| --- | --- |
| `POST`, `GET /v1/media/verifications` | `media.verification.create()`, `.list()` |
| `GET /v1/media/verifications/{id}` | `media.verification.retrieve()` |
| `GET /v1/media/verifications/{id}/link` | `media.verification.link()` |
| `POST /v1/media/verifications/{id}/refresh` | `media.verification.refresh()` |

## Billing and diagnostics

`jobs.observations()` exposes explicitly reported quantities and query observations.
`jobs.timings()` exposes available transport timing observations. `jobs.billing()`
keeps estimates, maximum liability, actual usage and customer charge separate.
An absent price, estimator or quantity remains unknown; it is not free usage.
`video.estimate()` can return 501 when no effective estimator is configured, even
though an owner-funded generation is permitted. Quantity is not inferred from
file duration or dimensions. Positive customer-priced video settlement has not
been actually verified by the personal FastRouter tests.

See [all implemented handler schemas](/docs/reference/handler-operations/) and the
[published OpenAPI JSON](/docs/openapi/handler-operations.json) for exact request
and response schemas. The [finite video acceptance matrix](https://github.com/niu-io/niu/blob/main/docs/reference/video-integration-acceptance-matrix.md)
and [SDK source](https://github.com/niu-io/niu/tree/main/sdks/javascript) record the
implementation and qualification details.

## 生成、等待与下载

请使用具备所选模型授权的工作空间 API 密钥。以下示例导入了 `@niu-io/sdk`，其源码位于 `sdks/javascript`；在使用其编译后的入口前，请先运行 `pnpm --filter @niu-io/sdk build` 构建该工作空间包。`NIU_BASE_URL` 是以 `/v1` 结尾的 Niu API 基础地址，而非上游模型供应商的 URL。请将 API 密钥保存在应用程序的服务端环境中。

```ts
import { NiuClient } from '@niu-io/sdk';

const niu = new NiuClient({
  baseURL: process.env.NIU_BASE_URL,
  apiKey: process.env.NIU_API_KEY!,
});

const models = await niu.video.models.list();
// 请先检查所选模型的 input_types、controls、mode 和 output。

// 请将此幂等键与该确切请求一同保存，以便在提交结果不确定时恢复状态。
const idempotencyKey = crypto.randomUUID();
const job = await niu.video.generate({
  model: 'fastrouter/seedance-2.5',
  prompt: 'A quiet ocean at sunrise, with slow camera movement.',
  durationSeconds: 5,
  resolution: '1080p',
  aspectRatio: '16:9',
  seed: 42,
  watermark: false,
}, { idempotencyKey });

const completed = await niu.video.jobs.wait(job.id, {
  intervalMs: 5_000,
  timeoutMs: 600_000,
});

if (completed.status === 'succeeded') {
  const availability = await niu.video.jobs.results.status(job.id);
  if (availability.video === 'available') {
    const response = await niu.video.jobs.results.retrieve(job.id, 'video');
    const bytes = await response.arrayBuffer();
    // 将字节保存在应用的持久化存储中，或直接流式转发响应。
  }
}
```

`video.generate()` 会将 `durationSeconds` 映射为 `duration`，将 `aspectRatio` 映射为 `ratio`，并将其他具名字段映射到 Niu 请求契约。额外的模型特定字段请使用 `controls` 传递（例如当模型显式声明支持时传入 `omni_reference_task_type`）。不能通过 `controls` 覆盖具名字段。系统不假设存在通用的 Seedance 参数范围或价格。`video.jobs.create()` 也接受更底层的 Niu `VideoCreateRequest` 请求文档。

### 状态恢复与不确定状态

Niu 在后端存储了任务、原始提交身份以及观测记录。在服务重启或浏览器缓存丢失后，可使用 `jobs.list()` 和 `jobs.retrieve()` 恢复已授权的保存任务。`jobs.refresh()` 会针对已绑定的上游任务发起一次显式查询。`jobs.wait()` 仅读取并刷新已保存的状态，绝不会提交新的生成请求。

| 状态 | 客户端应对操作 |
| --- | --- |
| `queued`、`running` | 继续等待，或稍后重新获取已保存的状态。 |
| `succeeded` | 下载前先检查结果可用性。 |
| `failed` | 读取观测记录和耗时信息；切勿将失败当作成功结果处理。 |
| `submission_unknown`、`reconciliation_required` | 保留原始身份标识并检查诊断信息；等待辅助方法会直接返回此状态，而不会自动重新提交。 |
| `unknown` | 等待辅助方法允许对初始处于未知状态的已保存任务执行一次刷新，若仍未解决则返回未知状态。 |

使用原始幂等键重放完全相同的创建请求文档，即可恢复已保存的尝试记录。使用相同幂等键但更改输入内容会导致冲突。返回 202 响应并不证明上游已完成生成；当请求处于不确定状态时，切勿为了重新运行而更换新的幂等键。中止等待操作仅会取消本地等待循环和 HTTP 请求，不会取消上游的视频任务。此处不提供取消上游任务的 API。

## 模型供应商资产管理

`niu.media` 通过 Niu 限定作用域的引用来管理由上游支持的资产。它独立于工作空间素材库上传功能。所选模型必须启用受支持的供应商资产渠道，且仍然受上游操作权限约束。读取和显式刷新操作需要传入模型别名。变更操作支持规范的 UUID 幂等键；更新和删除操作可使用当前的十进制字符串版本号（revision）。

```ts
const model = 'fastrouter/seedance-2.5';
const groups = await niu.media.groups.list({ model, limit: 20 });
const assets = await niu.media.assets.list({ model, limit: 20 });

// 创建资产分组或资产是一次性的上游操作。
const groupOperation = await niu.media.groups.create({
  model, name: 'Reference videos',
}, { idempotencyKey: crypto.randomUUID() });

if (groupOperation.group?.status === 'ready') {
  const assetOperation = await niu.media.assets.create({
    model,
    group_id: groupOperation.group.id,
    kind: 'video',
    name: 'Approved reference clip',
    url: process.env.APPROVED_REFERENCE_VIDEO_URL!,
  }, { idempotencyKey: crypto.randomUUID() });
  if (assetOperation.asset) {
    const saved = await niu.media.assets.refresh(assetOperation.asset.id, model);
    // 请等待实际状态变为 "active" 后，再将其作为生成参考使用。
  }
}
```

源 URL 必须符合该渠道接受的 HTTPS 与媒体规则，并且能够被上游服务直接拉取。需认证的 Niu 素材库 URL 并不会隐式成为公开的供应商上传 URL。处于挂起（pending）或未知（unknown）状态的变更操作并不代表上游已确认；请直接恢复其已保存的操作记录，切勿重复发送请求。

| HTTP 端点 | JavaScript SDK |
| --- | --- |

### 将准备（Preparation）与调度（Dispatch）分离

`media.operations.prepare(input, { idempotencyKey })` 会保存规范的操作记录，而不会向模型供应商发送请求。请保留确切的强类型输入和 UUID。执行调度（Dispatch）需要提供已确认的准备记录、其操作引用标识、完全相同的原始输入以及相同的幂等键。读取恢复出来的准备记录绝不会授权自动发起调度。操作历史中不会保留原始素材 URL，因此重新加载后的客户端无法凭空构造恢复负载。

只有未被认领的准备记录才能被取消。未知或已确认的结果保持只读。`admin.cancelPreparedMediaOperation(scope, operationId, model)` 使用当前工作空间的写入（Write）权限，可以在原始推理密钥过期或被吊销后放弃已保存的准备记录。它不会恢复推理权限，也不会向供应商发送请求。在当前密钥有效时，依然可以通过 `media.operations.cancel()` 取消操作。

使用 `admin.mediaOperationHistory(scope, { keyId, model })` 可以读取已保存的操作记录。即使原始密钥已过期或被吊销，只要具备当前工作空间的读取（Read）权限即可访问。该作用域涵盖了该确切密钥与模型下所有已保存的账户。传入 `contextGroupId` 可锁定某个已保存分组的不可变账户绑定。使用 `list`、`retrieve` 或 `retrieveByIdempotency` 不会刷新供应商状态，也不会恢复执行权限。

操作准备、取消和历史读取均已具备当前输入 API、构建后 SDK 以及独立持久化验收。浏览器中的调度成功与响应丢失恢复仍需单独验收。

### 将资产作为生成参考使用

```ts
// 仅当模型发现接口声明支持该参考类型、角色和控制参数时方可使用。
const activeAsset = assets.data.find(asset => asset.status === 'active' && asset.kind === 'video');
if (!activeAsset) throw new Error('An authorized active video asset is required');
const referenceJob = await niu.video.generate({
  model,
  prompt: 'Continue the motion in the approved reference clip.',
  references: [{ assetId: activeAsset.id, role: 'reference_video' }],
  controls: { omni_reference_task_type: 'reference' },
}, { idempotencyKey: crypto.randomUUID() });
```

此处的 `activeAsset` 是返回的且状态为 `active` 的 Niu 资产记录。在调度前，后端会再次检查作用域、确认状态、父分组、当前账户/模型、密钥授权以及策略。切勿传入上游资产 ID 或 `asset://` URI。普通 URL 参考使用 `{ kind, url, role }`；内联图像、可选的已审查/素材库参考及其限制条件各自保留独立的模型与授权契约。资产管理功能可用并不代表支持参考视频生成。在提交参考生成请求之前，请先检查所选模型允许的参考输入类型和控制参数。

控制台的素材（Materials）页面会在显式选择的工作空间、API 密钥和模型上下文下恢复已保存的操作记录。**Check saved status**（检查已保存状态）仅读取保留的操作记录，不会重试变更操作，也不会确立素材就绪状态。处于已准备（prepared）和未知（unknown）状态的结果仍属未确认状态，会阻止新的素材/分组写入。若历史读取失败，界面会保留现有记录并显示明确错误。记录缺失绝不能证明请求未发送；在持久化记录生成之前若发生传输不确定性，离开页面后目前无法恢复。

## 核验会话交接

这是一个上游真人核验会话，而非本地人脸识别。普通的文本生成不需要此步骤。仅当您选择的上游工作流需要且调用方已获授权时，才创建核验会话。

```ts
const created = await niu.media.verification.create({
  model,
  subjectName: 'Your authorized subject name',
}, { idempotencyKey: crypto.randomUUID() });
const session = created.data;
const handoff = await niu.media.verification.link(session.id, model);
// 仅向获授权的用户展示 handoff.verification_url，并保持其私密性。
// 用户完成核验后，发起一次显式观测刷新：
const observed = await niu.media.verification.refresh(session.id, model);
```

元数据读取操作会省略私有的上游令牌和链接。链接获取端点采用 `no-store`/`no-referrer` 保护处理；已过期的会话在服务重启或加密密钥轮换后不会重新获得有效链接。本实现不会断言真人核验流程已成功完成，也不会断言账户已获得额外的权益。

| HTTP 端点 | JavaScript SDK |
| --- | --- |
| `POST`, `GET /v1/media/verifications` | `media.verification.create()`, `.list()` |
| `GET /v1/media/verifications/{id}` | `media.verification.retrieve()` |
| `GET /v1/media/verifications/{id}/link` | `media.verification.link()` |
| `POST /v1/media/verifications/{id}/refresh` | `media.verification.refresh()` |

## 计费与诊断

`jobs.observations()` 暴露了显式上报的用量数值和查询观测记录。`jobs.timings()` 暴露了可用的传输耗时观测记录。`jobs.billing()` 将预估费用、最大负债敞口、实际用量和客户扣费严格区分开来。缺失的价格、估算器或用量数值将保持未知状态，绝不等同于免费使用。当未配置有效的估算器时，即使允许所有者出资（owner-funded）的生成，`video.estimate()` 也会返回 501。系统不会根据文件时长或尺寸推断用量。使用个人 FastRouter 账户进行的测试尚未实际验证正向的客户定价视频结算。

有关确切的请求与响应结构定义，请参阅[所有已实现的处理器模式（Schemas）](/docs/reference/handler-operations/)和[已发布的 OpenAPI JSON](/docs/openapi/handler-operations.json)。[有限视频验收矩阵](https://github.com/niu-io/niu/blob/main/docs/reference/video-integration-acceptance-matrix.md)和 [SDK 源码](https://github.com/niu-io/niu/tree/main/sdks/javascript)记录了完整的实现与验收细节。
