## Supplier configuration

Supplier identity owns independent credentials and model bindings. Provider names
identify technical adapters. Follow the
[configuration workflow](https://github.com/niu-io/niu/blob/main/docs/reference/supplier-key-isolation-live.md),
[offer directory](https://github.com/niu-io/niu/blob/main/docs/reference/supplier-offer-directory.md),
[configuration usage](https://github.com/niu-io/niu/blob/main/docs/reference/supplier-configuration-usage.md)
and [settlement history](https://github.com/niu-io/niu/blob/main/docs/reference/supplier-settlement-history.md).
Procurement rates and Supplier earnings are separate from customer charges.
Personal OpenRouter testing does not establish qualified commercial supply.

## Workspace keys

Keys inherit workspace model access and may narrow it. Spending, request rate,
token rate and unresolved-request concurrency are separate controls:

- [Customer spending caps](https://github.com/niu-io/niu/blob/main/docs/reference/api-key-spending-limits.md)
- [Request-rate limits](https://github.com/niu-io/niu/blob/main/docs/reference/api-key-request-rate-limits.md)
- [Estimated token budgets](https://github.com/niu-io/niu/blob/main/docs/reference/api-key-token-rate-limits.md)
- [Concurrent request limits](https://github.com/niu-io/niu/blob/main/docs/reference/api-key-concurrency-limits.md)

Rotation preserves the key's spending identity and applicable limits. Revocation
does not erase already dispatched work or its unresolved liability. Finite token
budgets require a supported bounded request shape; missing usage remains unknown.

## Customer money and recovery

Read the [payment integration inventory](https://github.com/niu-io/niu/blob/main/docs/reference/payment-aggregators.md)
for supported adapters and installation availability. Merchant activation is a
deployment concern; listing support does not grant balance. Browser returns do
not authorize funding. Approved credit is distinct from prepaid cash.

[Charge reconciliation](https://github.com/niu-io/niu/blob/main/docs/reference/customer-charge-reconciliation.md)
and [supplemental token usage](https://github.com/niu-io/niu/blob/main/docs/reference/token-category-reconciliation.md)
describe exact debits, unknown liabilities and original-price recovery. A recorded
usage receipt may precede settlement. Conflict errors must not be rendered as
zero usage or a successful financial operation.

## Video and invoices

The [media invoice contract](https://github.com/niu-io/niu/blob/main/docs/reference/media-invoice-integration.md)
explains durable jobs, result recovery, billing states and invoice boundaries.
A completed personal video may retain null customer charges. Customer-priced media
requires supported measured usage and pinned pricing; requested duration or
upstream expense must not be substituted for a customer charge.

Positive customer media invoices and nonempty commercial Supplier settlement
remain unverified. Actual personal video recovery and mixed personal-video /
customer-text invoicing do not establish those financial paths.

## Chat tools with structured final answers

Configured OpenAI-compatible routes can combine function tools with JSON object
or JSON schema output. A validated function turn is intermediate output; final
text must satisfy its JSON format. Both model capabilities must be declared, and
streaming additionally requires streamed-tool support. Niu does not execute tools.
Partial tool deltas are provisional until terminal validation.

The [combined Chat contract and actual verification](https://github.com/niu-io/niu/blob/main/docs/reference/chat-tools-structured-output.md)
record four real client round trips with independent usage/debit checks and
explicit unverified scope. A successful upstream example alone is not Niu
integration evidence, and this does not qualify a complete release gate.


## Customer request details

The [current request-detail verification](https://github.com/niu-io/niu/blob/main/docs/reference/customer-request-detail-live.md)
checks all 1,600 details from the current real-stream dataset and two retained
actual refusal states through ordinary scoped identities. Detail and list fields
match native timing, observed finish reasons, usage and exact customer charges.
Unknown execution/usage/amounts remain unknown; procurement and payload content
are excluded. Foreign-scope access and revoked readers are denied. This qualifies
the stated persisted metadata paths, not browser presentation or all protocols.


Ordinary text-mode tool streams now use the same bounded call/selection validator
as JSON tool streams, while permitting free-text final answers. Current actual
buffered/streamed text and JSON round trips were independently reconciled with
native usage and exact debits on `5a8a39c`. Clients must wait for validated
`[DONE]` before executing streamed calls; two actual malformed text-tool streams were independently verified to fail
without `[DONE]` while preserving reported usage and exact charges. Other malformed
upstream cases still require separate actual evidence. See the [text-mode validation checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/chat-tools-structured-output.md#plain-text-streamed-tool-validation--2026-10-12).


## Catalog eligibility storage failures

Published catalog reads check live Supplier eligibility and credential cooldowns.
The [bounded eligibility read checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/supplier-key-isolation-live.md#bounded-published-catalog-eligibility-read--2026-10-12)
verifies an actual workspace-key model-list refusal with HTTP 503 while storage
remains locked, followed by complete catalog and real-stream recovery. Treat 503
as unavailable, rather than empty setup or qualified cached supply. The exercised
query has transaction-local lock/statement limits; other reads, pool admission
and the complete HTTP deadline have separate scope.


## Find persisted failures after HTTP 200 headers

Use `status=recorded_failure` on request list and CSV export to select persisted
failure observations, including terminal SSE errors under HTTP 200. The full-range
summary uses the same selection. The SDK query supports this value. Existing
`delivery_failed` selects HTTP 400–599; missing diagnostics or uncertain execution
are not inferred as recorded failures. The [current filter contract and real verification](https://github.com/niu-io/niu/blob/main/docs/reference/recorded-request-failure-filter.md)
cover pagination, mixed success, SDK requests, exact charges, scope and restart.


## Saved video creation replay

The [bounded saved-identity checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/video-submission-intents.md#bounded-saved-submission-identity-read--2026-10-12)
verifies that a blocked identity read returns an unavailable error rather than
assuming the submission is absent. Compatible creation replay restored the same
actual succeeded video after lock release and restart, with one original
submission and no new billing. Its retrieved MP4 matched the retained result and
fully decoded. This checkpoint covers existing-job recovery; new generation,
intent-submit/browser restoration and paid media have separate verification scope.


## Recover saved top-ups when checkout is unavailable

Saved company top-up history and detail remain readable without an active
merchant checkout. Storage contention returns sanitized 503 rather than empty
history or paid status; history cursor/page reads share one bounded read-only
snapshot. The [current recovery-read checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/payment-aggregators.md#saved-customer-top-up-reads-under-contention--2026-10-12)
records actual lock refusal/recovery, ordinary-role authorization, unchanged
uncertain status and absent funding. Supported integration readiness and external
merchant activation are separate. Preserve known data when reads are unavailable.


## Company balance availability

Shared balance reads preserve one amount snapshot and return sanitized 503 when
storage waits exceed transaction-local limits. Preserve known data on failure;
do not show an unavailable read as zero balance or released liability. The
[current balance checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/customer-charge-reconciliation.md#bounded-company-balance-read--2026-10-12)
independently reconciles settled real-request debits and a retained uncertain
hold, including exact available credit, restart and cross-company denial.
A displayed available amount is not a guarantee of a later atomic admission.
