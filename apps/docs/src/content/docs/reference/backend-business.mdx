## Supplier configuration

Supplier identity owns independent credentials and model bindings. Provider names
identify technical adapters. Follow the
[configuration workflow](https://github.com/niu-io/niu/blob/main/docs/reference/supplier-key-isolation-live.md),
[offer directory](https://github.com/niu-io/niu/blob/main/docs/reference/supplier-offer-directory.md),
[configuration usage](https://github.com/niu-io/niu/blob/main/docs/reference/supplier-configuration-usage.md)
and [settlement history](https://github.com/niu-io/niu/blob/main/docs/reference/supplier-settlement-history.md).
Procurement rates and Supplier earnings are separate from customer charges.
Personal OpenRouter testing does not establish qualified commercial supply.

## Workspace keys

Keys inherit workspace model access and may narrow it. Spending, request rate,
token rate and unresolved-request concurrency are separate controls:

- [Customer spending caps](https://github.com/niu-io/niu/blob/main/docs/reference/api-key-spending-limits.md)
- [Request-rate limits](https://github.com/niu-io/niu/blob/main/docs/reference/api-key-request-rate-limits.md)
- [Estimated token budgets](https://github.com/niu-io/niu/blob/main/docs/reference/api-key-token-rate-limits.md)
- [Concurrent request limits](https://github.com/niu-io/niu/blob/main/docs/reference/api-key-concurrency-limits.md)

Rotation preserves the key's spending identity and applicable limits. Revocation
does not erase already dispatched work or its unresolved liability. Finite token
budgets require a supported bounded request shape; missing usage remains unknown.

## Chat tools with structured final answers

Configured OpenAI-compatible routes can combine function tools with JSON object
or JSON schema output. A validated function turn is intermediate output; final
text must satisfy its JSON format. Both model capabilities must be declared, and
streaming additionally requires streamed-tool support. Niu does not execute tools.
Partial tool deltas are provisional until terminal validation.

The [combined Chat contract and actual verification](https://github.com/niu-io/niu/blob/main/docs/reference/chat-tools-structured-output.md)
record four real client round trips with independent usage/debit checks and
explicit unverified scope. A successful upstream example alone is not Niu
integration evidence, and this does not qualify a complete release gate.

## Find persisted failures after HTTP 200 headers

Use `status=recorded_failure` on request list and CSV export to select persisted
failure observations, including terminal SSE errors under HTTP 200. The full-range
summary uses the same selection. The SDK query supports this value. Existing
`delivery_failed` selects HTTP 400–599; missing diagnostics or uncertain execution
are not inferred as recorded failures. The [current filter contract and real verification](https://github.com/niu-io/niu/blob/main/docs/reference/recorded-request-failure-filter.md)
cover pagination, mixed success, SDK requests, exact charges, scope and restart.

## Optional workspace key pagination

Supply `limit` (1–100) and optional `after` on key metadata reads to receive
`next_cursor`. Missing or foreign-workspace cursors return 409. With neither
parameter the complete compatibility response is unchanged. The SDK's
`listWorkspaceKeyPage` supports explicit pages; `listWorkspaceKeys` retains its
full-directory behavior. Actual traversals, a later tail insertion, scoped cursor
refusals and restart are recorded in the [bounded-page contract](https://github.com/niu-io/niu/blob/main/docs/reference/workspace-key-directory.md#optional-bounded-pages--2026-10-12).
Cursor references are internal API values and must not become product labels.


Page selection precedes latest-dispatch lookups. The [`8aba958` query-plan and
HTTP checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/workspace-key-directory.md#page-activity-lookup-cost--2026-10-12)
checks page-sized activity probes, complete SDK/HTTP traversal, scoped refusal
and restart on retained real-request data. That checkpoint predates the order
index below; its directory scan/sort observation describes the earlier revision.


Migration 0279 adds an index matching workspace ownership and keyset order.
The [indexed-page checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/workspace-key-directory.md#indexed-keyset-selection--2026-10-12)
verifies actual existing-data upgrade and first/middle-cursor index use without
sorting, together with complete HTTP/SDK traversal and scoped refusal/recovery.
This narrows read work on the exercised directory; broader capacity remains
unverified. Existing full-directory clients retain their compatibility response.


A [paced first-page read checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/workspace-key-directory.md#paced-indexed-first-page-reads--2026-10-12)
independently checks 1,200 actual 100-record reads at an offered 20/second,
restart/revocation and unchanged financial history. Local client p95 was 4.35 ms;
this is a first-page workload observation, not maximum capacity or a production
latency guarantee.

## Explicit key expiration choice

Key creation requires `ttl_seconds`: integers 1–31,536,000 retain finite expiry;
explicit `null` means no automatic expiration. Omission and invalid finite values
are refused. Metadata uses `expires_at_ms: null` for this state; display a
no-expiration label rather than interpreting null as a date. Rotation preserves
the state and lineage limits; revocation still blocks access. The [actual key
lifecycle checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/non-expiring-workspace-keys.md)
checks natural finite expiry, actual calls/debits, owner/viewer permissions,
SDK traversal, restart and spending refusal. Video and broader concurrent cases
remain unverified.


The SDK now supports `createWorkspaceKey`, `updateWorkspaceKey`,
`rotateWorkspaceKey` and `revokeWorkspaceKey`, with exported typed inputs/results.
Use integer metadata revisions and the existing decimal-string policy revisions.
The [live SDK checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/non-expiring-workspace-keys.md#javascript-lifecycle-client--2026-10-12)
checks actual HTTP methods, one-time no-store issuance, scoped denial, stale
updates, natural expiry, model calls/debits and revocation. Browser integration
remains separate.


The [saved-video key checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/non-expiring-workspace-keys.md#saved-video-access-with-no-expiration-keys--2026-10-12)
checks result reads using no-expiration keys before/after rotation and restart.
Actual downloaded MP4 bytes and full decode match the original persisted video;
IP denial, foreign scope, finite peer expiry and revocation block access. No new
generation or charge occurs. New video dispatch and customer-paid media remain
outside this read checkpoint.

## Supplier limit input errors

Supplier credential limit updates and history queries return a JSON 400 with a
generic message for invalid body/query extraction, after management authorization.
They do not echo extractor diagnostics. Missing limits are rejected; explicit
null remains unlimited. [Current HTTP and independent database evidence](https://github.com/niu-io/niu/blob/main/docs/reference/supplier-credential-rate-controls.md#input-error-contract--2026-10-12)
covers rejected inputs, 401/403 authorization, valid revision advancement, stale
409, restart and unchanged original customer charges.

## Guardrails policy storage waits

Policy snapshot reads use bounded read-only storage transactions and return
sanitized 503 on exceeded waits, without substituting an empty policy. The
[actual video/text checkpoint](https://github.com/niu-io/niu/blob/main/docs/reference/guardrail-snapshot-storage-waits.md)

response and exact charge survive restart. This does not bound all Guardrails
operations, detector processing, authentication or pool acquisition.
