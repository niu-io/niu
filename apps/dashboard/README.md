# Niu dashboard

React Router v8 Data Mode and Vite dashboard served by the Niu gateway in production. Run `pnpm build:dashboard` from the repository root to build its static assets.

Use the shared shadcn/ui primitives in `app/components/ui` for controls and `@tabler/icons-react` / `lucide-react` for product icons. Keep icons embedded in installed shadcn components consistent with their upstream source. `components.json` configures the official registry and local aliases. Tailwind theme values map to the approved niu.io tokens in `branding/tokens.css`; preserve these tokens when adding components. `app/styles.css` is the stylesheet entry point and imports the ordered modules under `app/styles/`; keep that import order because it is the cascade order. Workspace pages are nested under `/workspaces/:workspace/…`; the path is a UI selector and does not grant access. Server APIs remain responsible for authorization.

## Application layout & data ownership

Keep route modules, application shell, feature UI, and shared code in separate places under `app/`:

- `app/entry.client.tsx` and `app/root.tsx` mount the React Router v8 Data Mode provider (`<RouterProvider router={router} />`) and global branding/currency providers. The dashboard uses Data Mode (`createBrowserRouter` / `createMemoryRouter`), not React Router Framework Mode.
- `app/router-tree.tsx` assembles the Data Mode route tree from domain modules under `app/shell/routes/` (global/account, administration, workspace). It owns the root frame, nested outlet `<AppError />` boundaries, lazy chunk binding (`bindLazy` in `app/shell/lazy-route.ts`), typed `handle` metadata, and `createDashboardRouter` / `createDashboardMemoryRouter` wired with `getContext: createRouterContextProvider` (`dashboardRouterContext`). `app/routes.ts` is the matching React Router config manifest for the Vite build. Keep the two in sync and add new routes to the domain module that owns them.
- `app/shell` owns the persistent application shell (`AppLayout`), authenticated principal and effective-authority verification (`/api/v1/session`), workspace directory resolution (`/api/v1/organizations`, `/api/v1/workspaces`), navigation hover/focus prefetching (`prefetchRouteIntent`), and router context publishing (`router-context.ts`). Protected workspace views do not render until the current session authority's workspaces are verified.
- **Router vs. SWR cache ownership**:
  - **React Router Data Mode (`app/lib/route-data.ts`)** owns URL matching, `dashboardRouterContext` injection via `RouterContextProvider`, critical route-entry `loader` execution (returning warm cache hits synchronously, starting non-blocking cancellation-bound loads on cold navigations so route skeletons render immediately without trapping transitions, and awaiting fresh reads when revalidating invalidated entries), `routeShouldRevalidate` policies (skipping transient hash/settings-modal URL changes while revalidating on scope changes and explicit `revalidator.revalidate()`), and outlet-scoped `<AppError />` boundary recovery that preserves the navigation shell.
  - **SWR Query Cache (`app/lib/query-cache.ts`)** owns principal/authority isolation (`syncCacheAuthority`, purging memory and `sessionStorage` on identity or permission changes), monotonic request/invalidation generation tracking (preventing obsolete or pre-mutation reads from overwriting newer state), Frame-0 synchronous reads (`peekQuery` / `useCachedQuery`), and mutation invalidation (`invalidateForMutation`, which invalidates matching cache/in-flight reads and notifies `AppLayout`'s `useRevalidator()`).
- `app/features/<feature>/page.tsx` is the lazy route entry for that feature. Critical data-bearing route entries export `clientLoader` and `shouldRevalidate` alongside their default page component. Idempotent form mutations export a route `clientAction` and use `useFetcher`/`fetcher.state` at the call site; see [the fetcher mutation pattern](../../docs/ux/fetcher-route-actions-2026-11-06.md). Streaming, autosave, upload, OAuth/connect and multi-step prepare/publish operations that are not a single form save continue to use `useCachedQuery` and `app/lib/api-client.ts` (`request`, `cachedGet`).
- **Form mutation pattern**: keep the network operation in a small feature helper, return discriminated action data for success and expected failures instead of throwing, render pending/disabled state from `fetcher.state`, and apply a confirmed result explicitly to shell state plus the query cache. Scope local success/error state by resource id so a response from a previous workspace cannot overwrite the current form, while still applying a confirmed rename to the shared workspace directory. Preserve uncertain-outcome recovery for idempotent writes: keep the typed value, explain that the change may or may not have been saved, and let the user retry explicitly. `clientAction` is the framework SPA export; `bindLazy` maps it to the Data Mode `action` slot. Do not export both `action` and `clientAction` from a framework SPA route.
- `app/features/<feature>/components` contains page views and feature-only UI, with deeper folders for larger features. Feature-only request helpers, hooks, types, and pure utilities stay beside that feature; shared primitives live in `app/components/ui` and cross-feature utilities live in `app/lib`.
- `test/app` and `test/features/<feature>` hold route, lifecycle, and feature integration tests. `test/lib` holds focused tests for shared domain and cache logic; shared visual primitives do not get isolated unit tests.

Use the `@/` alias for imports from `app`. Navigation is URL-backed, and cross-feature drill-down context is encoded in query parameters so deep links and reloads preserve the selected scope. Keep product behavior and API contracts in Niu-owned modules.

The root `pnpm dev` command serves the hot-reloading dashboard and proxies API requests through one browser origin at `http://127.0.0.1:2566`. Sign-in uses a persisted member account and normal browser sessions. See [the development guide](../../scripts/DEV.md) for account seeding and startup details.

## Frontend lint and CSS hygiene

Run the gate from this directory with `pnpm lint`, or from the repository root with `pnpm lint:dashboard`. `pnpm check` runs the same gate after type generation and `tsc`. The gate has four steps:

- `node scripts/check-hygiene.mjs` preserves the repository-specific ownership rules.
- `node scripts/check-module-size.mjs` enforces the 800-line reviewability threshold for modules under `app/` (see below).
- `node scripts/lint.mjs` runs Biome's recommended rules over `app/`, `scripts/` and `test/` (TypeScript, TSX, JavaScript, MJS and CSS) and compares the diagnostic counts with `lint-baseline.json`. Any count above the baseline fails. The baseline records 1,208 existing diagnostics; lower it with `pnpm lint:update-baseline` only after reviewing the reduced count. New code should not rely on the baseline for new debt, and a deliberate increase must be explained in review.
- `node scripts/check-css-usage.mjs` is the reproducible unused-CSS audit. It protects class names composed in `className`, `cn()` and `classList` expressions, treats `:not()`/`:is()`/`:where()` arguments as optional rather than required, and fails when an unreferenced class remains in a removable selector. Use `--report` for the audit and `--write` to remove proof-positive dead selectors; neither mode guesses at runtime-composed classes.

Biome parses Tailwind directives through `css.parser.tailwindDirectives`. Do not disable the formatter setting or add formatting to this gate; it exists to catch correctness and dead-code regressions without rewriting the tree.

## Module size and route namespaces

Keep a route/page module at or below **800 lines**. This is a reviewability limit, not a functional boundary: one reviewer should be able to read the module's state, data flow and rendered branches in one sitting. New modules above the limit fail `pnpm lint` unless they are listed in `module-size-baseline.json` with a reason. Existing exceptions are split by domain over time; adding an exception requires explaining why a split is unsafe or why the module is data-only. Do not raise the threshold or refresh a grown exception without explaining the change in review.

Route definitions belong to the domain module that owns them: `app/shell/routes/global-routes.tsx` (signed-in global and legacy provider URLs), `app/shell/routes/account-routes.tsx` (models, settings, activity, chat), `app/shell/routes/admin-routes.tsx` (administration) and `app/shell/routes/workspace-routes.tsx` (workspace scope). `app/shell/legacy-redirects.tsx` holds retired-URL loaders and redirect components. `test/app/router-tree.parity.test.ts` snapshots every route's id, absolute path, loader and element wiring; update the snapshot only for an intentional route change and review the diff.

## Release metadata

The container build embeds the version from the repository's `VERSION` file in About. Distributors can override it with the `VITE_NIU_VERSION` Docker build argument and may provide a verified release date with `VITE_NIU_RELEASE_DATE` (ISO date, `YYYY-MM-DD`). Standalone dashboard builds can set the corresponding environment variables. An unversioned local build displays “Development build”; About omits the release date when none is supplied rather than treating build time as a release date.
